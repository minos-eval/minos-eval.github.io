Know whether your LLM tools are good enough to ship, and to stay shipped.

Minos is an evaluation framework for LLM-based applications. It drafts an evaluation pipeline from the artifacts you already have, checks its own LLM judges against human labels, and sends uncertain cases to people instead of guessing.

The problem

Conventional tests assume a stable right answer. LLM apps rarely have one.

Chatbots, code-review bots and test generators are now part of everyday software. Evaluating them breaks the assumptions that ordinary software testing relies on.

Many valid answers

Outputs are open-ended. Two different responses can both be correct, so exact-match checks miss real failures or flag good answers.

Results change between runs

The same input can produce a different answer, and a different verdict from the evaluator, every time it runs. One run is not evidence.

Judges are not always right

LLM-as-a-judge scales review, but its decisions do not always agree with human experts. A judge that is never checked becomes a hidden risk.

How it works

One evaluation lifecycle, from first connection to production.

The same evidence and decision structure is used before release and after it, so what you test and what you observe stay comparable.

  1. 01

    Register

    Connect the app and the tools it can call through a common interface. Missing or incompatible information is rejected with an explanation.

  2. 02

    Induce

    No evaluation pipeline yet? Minos drafts one from your documentation, schemas, traces and past results.

    Engineer approves
  3. 03

    Evaluate

    Each case runs several times on a versioned dataset. Deterministic checks go first, then metrics, then LLM judges.

  4. 04

    Gate

    After your conventional tests, the CI/CD pipeline asks Minos for a decision: pass, fail or manual review.

  5. 05

    Monitor

    Privacy-filtered production traces are checked against approved rules. Confirmed failures become regression cases.

    Engineer approves
Inside an evaluation

Cheap and certain first. Model judges only where they are needed.

Rules decide what rules can decide. LLM judges handle the semantic criteria that remain, and their verdicts only count when the confidence is high enough.

  1. 1. Deterministic checks

    Same evidence and evaluator version, same result, every time.

    output formattool selectedtool argumentsexecution result

  2. 2. Reference and task metrics

    Compare against expected behavior and reference data where it exists.

    correctnessfaithfulnesspolicy compliancesafety

  3. 3. LLM judges, for what is left

    Unresolved criteria are judged against the collected evidence. Each verdict gets a calibrated confidence value.

Above threshold

Automatic pass or fail, recorded with its evidence.

Below threshold

No automatic decision. The case goes to an evaluation engineer.

Built-in limits

Every evaluation configuration sets how much it is allowed to spend.

Our approach

Three things existing evaluation tools do not document.

CI/CD gates and production monitoring are table stakes. These three are where Minos differs.

01 · Cold start

Start from the artifacts you already have.

Most platforms expect you to arrive with a dataset and evaluators. Minos reads what the team already owns and proposes a first evaluation card, including what it could not figure out.

  • Proposes cases, methods, metrics and initial decision rules
  • Reports missing evidence and unsupported assumptions
  • Nothing runs until an evaluation engineer approves it

02 · Judge reliability

The judge is evaluated too.

An LLM judge is treated as a component that can be wrong. Minos compares its decisions with expert labels, measures how consistent it is across repeated runs, and attaches a confidence value to every verdict.

  • Agreement with an expert-labeled set is reported, not assumed
  • Below the approved threshold, the system abstains
  • Human overrides keep the original automated result

03 · Human-guided calibration

Spend expert time where it teaches the most.

Instead of sampling cases at random, Minos ranks them by how informative or risky they are. Approved human decisions go back into the calibration set and the next round picks new cases.

  • Prioritizes low confidence, disagreement, inconsistency and risk
  • Reviewers see the input, output, tool calls, evidence and why the case was picked
  • Can ask a domain expert about a specific case

Principles

Evidence over confidence.

  • Reproducible resultsEach result records the dataset, prompt, model, evaluator, adapter and policy versions used.
  • People decide when it is unclearUncertain and high-impact cases go to an evaluation engineer, never to a guess.
  • Your data stays where it belongsNo project data goes to an external model provider without approval. Personal data is processed under KVKK.
  • Isolated executionExternal repositories run in isolated environments without access to protected credentials.
